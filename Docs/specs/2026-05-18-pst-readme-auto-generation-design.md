# PST README 自动生成设计

## Overview

为 project-state-tracker 增加自动生成/更新 README 的能力，使任何 Agent（特别是 Execute-LandingPrompt）能通过读取一个文件快速理解项目的完整结构、状态和依赖关系。

生成两个 README：
1. **PST 项目根 README**（`<pst_root>/README.md`）— 整个管理区域的入口索引
2. **Landing Prompt README**（`<pst_root>/prompts/landing/README.md`）— 满足 ELP 协议 + Agent 上下文

## 决策记录

| # | 问题 | 决策 |
|---|------|------|
| 1 | README 生成位置 | 两处：PST 根 + prompts/landing/ |
| 2 | 内容粒度 | 最完整：目录树 + 状态 + 依赖图 + handoff 摘要 |
| 3 | ELP front-matter 数据来源 | 从 status.yaml 的 meta 字段读取 |
| 4 | 触发时机 | 集成到 render_status.py，与 views 一起渲染 |
| 5 | 已有 front-matter 处理 | 保留用户手写 front-matter，只更新正文 |

## §1 meta schema 扩展

在 `status.yaml` 的 `meta` 中新增以下可选字段：

```yaml
meta:
  project_name: "Plan_Viewer"
  source_root: "Q:\\Plan_Viewer"          # 新增：源码根目录
  scope:                                   # 新增：允许操作的路径列表
    - "Q:\\Plan_Viewer"
  pst_root: "Q:\\Plan_Viewer\\Docs"       # 新增：PST 管理区域根目录
  coding_standards: "Follow existing patterns. Match surrounding file style."  # 新增：可选
  # ... 原有字段不变
```

**字段规则：**

| 字段 | 必填 | 默认值 | 用途 |
|------|------|--------|------|
| `source_root` | 否 | 无（缺失时 README 2 标记 `"<未配置>"`) | ELP 的源码操作根目录 |
| `scope` | 否 | `[source_root, pst_root]` | ELP 允许操作的路径范围 |
| `pst_root` | 否 | status.yaml 所在目录的父目录 | PST 管理区域根，README 写入位置 |
| `coding_standards` | 否 | 无（缺失时不生成该 section） | ELP 执行代码修改时遵循的规范 |

## §2 README 1：PST 项目根 README

**输出路径：** `<pst_root>/README.md`

**内容结构：**

```markdown
# <project_name> — Project State Overview

> Auto-generated by project-state-tracker. Do not hand-edit.
> Last updated: <ISO timestamp>

## 目录结构

research/           — 调研事实与证据 (N files)
decisions/          — 基于调研的决策 (N files)
plan/               — 执行计划与设计 (N files)
prompts/landing/    — 实施 Prompt (N files)
prompts/test/       — 验证 Prompt (N files)
status/status.yaml  — 状态单一真相源
views/              — 只读派生视图
tools/              — Python 状态管理脚本

## Artifact 状态总览

| ID | Type | Status | Path |
|----|------|--------|------|
| R-001 | research | reviewed | research/R-001-... |
| D-001 | decision | accepted | decisions/D-001-... |
| ... | ... | ... | ... |

## 依赖关系图

R-001 ← D-001 ← Plan.dashboard-design
                ↖ LP-001

## Handoff 上下文

| HC | Producer | Status | Version | Consumers |
|----|----------|--------|---------|-----------|
(无活跃 handoff)

## Blockers

(无阻塞项)

## 快速导航

- 完整状态数据: status/status.yaml
- 变更日志: views/change_log_view.md
- Prompt 执行链: views/prompt_chain_view.md
```

**生成规则：**

1. 目录树：扫描 pst_root 下实际存在的 PST 标准子目录（research/、decisions/、plan/、prompts/landing/、prompts/test/、status/、views/、tools/），统计每个目录中的文件数（排除 .gitkeep）
2. Artifact 表：从 `artifacts` + `research_findings` + `decisions` 合并，按 ID 排序
3. 依赖图：遍历所有 artifacts 的 `depends_on` 字段，构建有向图。格式为每行一条边：`A ← B` 表示 B depends_on A。按拓扑层级分组，同层级的节点对齐。如果图过大（>15 条边），只显示 LP 相关的子图并注明"完整依赖图见 status.yaml"
4. Handoff 表：从 `handoff_contexts` 读取，如果为空显示"无活跃 handoff"
5. Blockers：从 `blockers` 中筛选 `status == "open"`，如果为空显示"无阻塞项"

## §3 README 2：Landing Prompt README

**输出路径：** `<pst_root>/prompts/landing/README.md`

**内容结构：**

```markdown
---
source_root: "<从 meta.source_root>"
scope:
  - "<从 meta.scope>"
pst_root: "<从 meta.pst_root>"
---

# <project_name> LandingPrompt

> Auto-generated body by project-state-tracker. Front-matter preserved if pre-existing.
> Last updated: <ISO timestamp>

## LP 序列

LP-001 -> LP-002 -> LP-003

## Coding Standards

<从 meta.coding_standards 读取>

## 当前 LP 状态

| ID | Status | Depends On | Produces HC |
|----|--------|------------|-------------|
| LP-001 | ready | Plan.x | HC-001 |

## Handoff 上下文摘要

| HC | Facts | Constraints | Consumed By |
|----|-------|-------------|-------------|
| HC-001 | fact1; fact2 | constraint1 | LP-002 |
```

**生成规则：**

1. **Front-matter 保留逻辑：**
   - 文件已存在 → 读取并解析，保留原有 YAML front-matter 不覆盖，只替换 `---` 之后的正文
   - 文件不存在 → 从 meta 字段生成完整 front-matter + 正文
   - `meta.source_root` 缺失 → front-matter 中标记 `source_root: "<未配置>"`

2. **LP 序列生成：**
   - 从 artifacts 中筛选 `type == "landing_prompt"`
   - 按 `depends_on` 进行拓扑排序
   - 用 `->` 箭头连接，表示执行顺序
   - 如果无 LP artifacts → 显示"尚无已注册的 Landing Prompt"

3. **Coding Standards：**
   - 从 `meta.coding_standards` 读取
   - 如果字段缺失 → 不生成此 section

4. **LP 状态表：**
   - 列出所有 LP artifacts 的 ID、status、depends_on、produces_handoffs

5. **Handoff 摘要表：**
   - 从 `handoff_contexts` 中筛选与 LP 相关的 HC
   - facts 和 constraints 用分号连接为单行摘要

### front-matter 保留逻辑伪代码

```python
def write_with_frontmatter_preservation(path: Path, new_body: str):
    """写入 README，保留已有的 YAML front-matter"""
    if path.exists():
        existing = path.read_text(encoding="utf-8")
        if existing.startswith("---"):
            # 找到第二个 ---
            end_idx = existing.index("---", 3)
            frontmatter = existing[:end_idx + 3]
            final = frontmatter + "\n\n" + new_body
        else:
            final = new_body
    else:
        final = new_body
    path.write_text(final, encoding="utf-8")
```

## §6 边界情况

| 情况 | 行为 |
|------|------|
| `meta.source_root` 缺失 | README 1 正常生成（不含 source_root 信息）；README 2 front-matter 标记 `"<未配置>"` |
| 无 LP artifacts | README 2 的 LP 序列显示"尚无已注册的 Landing Prompt"；LP 状态表为空 |
| 无 handoff_contexts | 两个 README 的 handoff section 显示"无活跃 handoff" |
| 无 blockers | README 1 的 blocker section 显示"无阻塞项" |
| `prompts/landing/README.md` 有用户手写 front-matter | 保留 front-matter，只更新正文 |
| `prompts/landing/` 目录不存在 | 自动创建 |
| 循环依赖（LP 之间） | 拓扑排序检测到环 → 按 ID 字母序排列，附加警告注释 |
| artifacts 数量为 0 | README 1 的 artifact 表显示"无已注册 artifact" |
